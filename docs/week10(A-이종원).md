## A-1. 검색 경로 추적

1. 정상 검색
   - 검색어: 테스트
   - 검색 결과: 2건
   - 검색된 제목: 테스트1, HTML 테스트

2. Network 요청 확인
   - 요청 방식: GET
   - 요청 주소: http://localhost:5173/api/posts?q=%ED%85%8C%EC%8A%A4%ED%8A%B8
   - Payload의 q 값: 테스트

3. React에서 검색 요청을 만드는 위치
   - 파일: client/src/pages/PostList.tsx
   - 관련 코드: ``setPosts(await api<Post[]>(`/api/posts?q=${encodeURIComponent(keyword)}`));``
   - 역할: 검색어 keyword를 q에 넣어 서버에 GET 요청을 보내고, 응답받은 게시글 목록을 화면에 반영한다.

4. 서버에서 검색어를 읽는 위치
   - 파일: server/src/routes/posts.ts
   - 코드: `const rawQ = req.query.q;`
   - 요청의 q 값을 받아 검사한 뒤 검색어로 사용한다.

5. SQL을 실행하는 위치
   - 파일: server/src/routes/posts.ts
   - 코드: `const [rows] = await pool.execute(...)`
   - DB에서 제목에 검색어가 포함된 게시글을 조회한다.
   - 조회 결과는 rows에 담고, `res.json(rows)`로 응답한다.

전체 흐름:  
검색어 입력 → React에서 요청 생성 → 서버에서 q 읽기 → DB 조회 → JSON 응답 → 게시글 목록 표시

## A-2. 검색 입력 검증과 SQL 수정

- 수정 파일: `server/src/routes/posts.ts`
- 수정 대상: `GET /api/posts`의 게시글 검색 처리
- 외부 입력: `req.query.q`로 전달되는 검색어

### 수정 전 문제

검색어를 `LIKE '%${q}%'`처럼 SQL 안에 직접 넣고 있어서, 입력에 따라 검색 명령의 의미가 바뀔 수 있었다.

또한 `String(...)`은 입력을 문자열로 바꾸기만 하므로 배열 입력을 거절하지 못했다. 검색어 길이를 검사하는 코드도 없었다.

### 수정 내용

1. 검색어를 변환하지 않고 `rawQ`에 받아, 문자열이 아닌 값이면 400으로 거절하도록 했다.
2. 검색어가 없으면 빈 문자열을 사용하도록 했다.
3. `q.length > 50` 조건을 추가하여 50자를 초과하면 400으로 거절하도록 했다.
4. SQL에는 `LIKE ?`를 쓰고, 검색값은 `["%테스트%"]` 형태의 값 배열로 따로 전달하도록 했다. 실제 코드는 ``[`%${q}%`]``이다.
5. `pool.execute`로 SQL과 값을 분리해서 실행하도록 했다.

### 입력 검증 확인 결과

검사 추가 전에는 중복된 q와 51자 검색어 모두 200과 빈 목록 `[]`로 처리됐다.

1. `q=테스트&q=과제` 요청: 400으로 거절됐고, `q must be a string` 응답이 왔다.
2. 51자 검색어: 400으로 거절됐고, `q must be 50 characters or fewer` 응답이 왔다.
3. 50자 검색어: 200과 빈 목록 `[]`가 응답으로 왔다.

정상 검색과 SQL 입력에 대한 추가 테스트 결과는 A-3에 기록한다.

## A-3. 검색 테스트

게시글 건수는 각 테스트를 진행한 당시의 결과이다.

1. `과제` 검색: 1건이 나왔고, 제목은 「과제 제출 질문」이었다.
2. 빈 검색어로 검색: 전체 게시글 6건이 나왔다.
3. q를 보내지 않은 요청: 전체 게시글 6개를 JSON으로 받았다.
4. `O'Reilly` 검색: 검색 결과는 0건이었다.
5. `' OR 1=1 --` 뒤에 공백 한 칸을 넣어 검색: 결과는 0건이었고, 전체 글이 검색되지 않았다.
6. `q=테스트&q=과제` 요청: 중복된 q를 400으로 거절했다.
7. 50자 검색어: 200과 빈 목록 `[]`가 반환됐다.
8. 51자 검색어: 400으로 거절했다.
9. 제목에 객체 `{ a: 1 }` 전달: 자료형 검사 추가 후 400으로 거절했다.
10. 정상적인 문자열 제목과 내용으로 글쓰기: 등록에 성공했고, 상세 화면에서 제목과 내용을 확인했다.

### 객체 입력 테스트에서 확인한 문제와 수정

처음에는 제목에 객체를 보내도 200과 `{"message":"created","id":10}`이 반환됐다. 글쓰기 처리에 제목이 문자열인지 확인하는 코드가 없었기 때문이다.

글 등록을 처리하는 부분에서 제목이나 내용이 문자열이 아니면 400으로 거절하는 검사를 추가했다. 같은 객체 입력을 다시 보냈을 때 다음 응답을 확인했다.

`{"message":"title and content must be strings"}`
